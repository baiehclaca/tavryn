01 THE IDEA

Powerful software needs
visible limits.

Modern programs can read sensitive data, change records, send messages, and spend money. Those powers are often scattered through code, configuration, and third-party tools.

Tavryn’s goal is to make authority part of the program contract. Code requests effects. The host grants bounded access. The runtime mediates what actually happens.

{ }

Declare

External effects should be visible in source and, eventually, in function signatures.

⊂

Bound

A host grants only the resources and actions a program is allowed to use.

↗

Explain

Permission decisions should be recorded without copying private content into logs.

02 THE LANGUAGE TODAY

Readable intent.
Separate consent.

The experimental interpreter supports local file reads and writes. This example creates a draft file; it does not send a message.

draft.tav
# Ask for the paths this program needs
needs read "inbox/*.txt"
needs write "drafts/*.txt"

let message = read("inbox/message.txt")
let reply = "Draft reply: " + message
write("drafts/reply.txt", reply)
say("Saved the draft.")

03 THE LONG VIEW

Built to earn
a 1.0 release.

A language becomes dependable through specification, tooling, independent use, and years of maintenance. Each stage below has a release gate, not just a date.

YEAR 01

Define the core

Choose one real automation task. Specify functions, types, and effects; build a typed interpreter and conformance suite.

GATE / Independent developers complete the task safely.
YEAR 02

Connect to existing systems

Build bounded host APIs, effect-aware modules, interoperability, benchmarks, and external security review.

GATE / Permissions hold across modules and adapters.
YEAR 03

Make it maintainable

Deliver packages, reproducible builds, debugger and editor support, migration guides, and compatibility rules.

GATE / Teams maintain nontrivial services independently.
YEARS 04–05

Prove production readiness

Test multiple platforms, repeat audits, stabilize semantics, establish governance, and release 1.0 only when the evidence supports it.

GATE / Third parties can verify and upgrade with confidence.

04 PROJECT STATUS

Open work.
Honest claims.

Tavryn currently has a working interpreter for a small language and a narrow local-file permission model. It does not yet have general-purpose functions, a type system, networking, packages, or a production security audit.

The name is provisional, and licensing and contributor terms must be settled before an open-source release. The project is public so its direction and limitations can be reviewed.
